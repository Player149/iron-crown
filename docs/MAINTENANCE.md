# 유지보수와 이식 범위

## 게임 규칙

| 항목 | 구현값 |
|---|---|
| 모드 | 싱글플레이 + AI 기사 15 + 몬스터 28 |
| 레벨 | 1–40 |
| 기본 HP | 100 + (레벨-1) × 300/39 |
| 기본 ST | 100 + (레벨-1) × 100/39 |
| 진화 | Lv.5 / 15 / 25, E / R / Q 해금 |
| 레벨업 | 무작위 스탯 3개 중 1개, 최대 HP의 15% 회복 |
| HP 회복 | 피해 주고받음이 5초 없으면 최대 HP의 10%/초 |
| ST 회복 | 20/초, 막기 중 중단 |
| 전투 상태 | 기사끼리 명중 후 5초, 양쪽 갱신. 몬스터 제외 |
| 전투 중 소모 | 공격 15, 기술 25, 막기 성공 5, 막힌 공격자 추가 15 |
| 비전투 | 공격·기술 ST 소모 없음 |
| 탈진 | 막기 비용으로 ST가 0이면 2초 조작 불가 |
| 기사 처치 | HP·ST 완전 회복, 전투·탈진 해제 |
| 막기 | 이동 속도 50%, 기본 피해 감소 64% |
| 보스 | 300초마다, Lv.10 이상 2명부터, 최대 180초 |
| 보스 보정 | 원래 최대HP × (1 + (참가자-1) × 0.7), 공격 4배, 공속 0.55배, 크기 1.62배 |
| 도전자 | 추가 능력치 10%, 외형과 스킬 유지 |
| 보스전 종료 | 참가 전 상태 복원, 사망도 복원, 보스전 XP 미정/미지급 |
| 보상 | 도전자 승리 시 100000 × 인원 × 기여피해/보스최대HP; 보스 300000 × 처치/인원 |
| 룬/상점 | 룬 8종, 각 최대5, 장착3, 상자800, Lv.5 시작권1400 |
| 부활 | 800 / 1800 / 4000골드, 최대3회 |

수치는 원본 v1.3 기준을 이식했습니다. 보스 HP는 기존 구현의 **기본 HP + 추가 HP** 해석을 유지합니다. 실제 결제, 서버, 멀티플레이는 포함하지 않습니다. 기기별 브라우저 성능 및 화면 비율에 따라 조작감이 달라질 수 있습니다.

## 파일 역할

- `arena.gd`: 게임 흐름, 피해, XP, 보스, 라운드 보상.
- `fighter.gd`: 이동, AI, 평타·스킬, HP/ST, 회복, 캐릭터 시각 표현.
- `catalog.gd`: 스탯/룬/진화 정의와 효과. 새 항목은 표시용 배열과 적용 로직을 함께 변경.
- `meta.gd`: 로컬 영구 진행. 이전 HTML 세이브 최초 가져오기.
- `ui.gd`: 메뉴, 선택창, 상점, HUD. 정적 레이아웃은 ui.tscn.
- `touch_controls.gd`: 멀티터치 이동 및 전투 입력. 키보드와 분리.
- `balance.gd` + `balance.tres`: Inspector에서 바꾸는 공통 수치.

애니메이션은 시각 표현이며 공격 판정은 `fighter.gd`에 있습니다. 타격 타이밍을 특정 프레임으로 옮기려면 AnimationPlayer의 메서드 트랙과 피해 함수 호출을 연결하세요. 지금은 버튼 입력 시 판정이 발생하는 기존 게임 방식입니다.

## Git과 배포

`main`에는 개발 원본만 관리하고 `.godot/`와 `build/`는 제외합니다. Actions가 빌드 산출물을 Pages에 직접 전달합니다. `gh-pages` 브랜치는 필요하지 않습니다. 모바일 편집 전에 pull, 편집 후 commit/push, PC에서 다시 pull합니다. 동시에 같은 씬을 수정하면 충돌 해결이 필요할 수 있습니다.

기획 변경 요청 → Notion 규칙 확인 → 코드/씬 변경 → headless 테스트 및 Web export → GitHub Actions 성공 → 실제 Pages 확인 → Notion 변경 이력 업데이트 순서로 유지보수합니다.

## 검증

`tests/run.gd`는 체력·스태미나 성장/회복/소모, 탈진, 몬스터 예외, 처치 회복, 진화 시점, 기술 실행, 보스 스탯과 복원을 검증합니다. 에디터 UI/실기기 터치 조작 검증은 자동 수치 테스트와 별도입니다.
